# AVALON 前端手动测试用例文档（5 人局）

## 1. 测试目标

在微信开发者工具模拟器中，手动验证前端各阶段 UI 与游戏流程。无自动化前端测试框架，依赖手动 + AI 机器人（`ai-http.js`）驱动多玩家场景。

- 覆盖 5 人局完整游戏生命周期（含轮次循环、流车回环、强制车、刺杀阶段、湖仙/兰斯等特殊环节）。
- 覆盖阶段状态机 UI：roleReveal / preNominate / speakingOrder / discussion / teamVote / missionVote / lake / lancelot / assassination / gameEnd。
- 覆盖渐变卡片、标签体系、预选车展示、复选框限制、历史记录、返回房间等交互细节。
- 覆盖流程路径：三好车刺杀、三坏车获胜、流车强制车、刺客主动刺杀。

## 2. 生命周期

### 2.1 生命周期总览图

```
  开局
 (roleReveal)
    |  全员确认身份
    v
    +------------------------------------------------------+
    |               轮次循环 (第 1~5 轮)                    |
    |                                                      |
    | [预选] --> [发言序] --> [讨论] --确认发车--> [队伍投票] |
    |  preNominate speakingOrder discussion    teamVote    |
    |    ^                                        | 通过   |
    |    | 流车(下一位车主)                          |       |
    |    +-----------------------------------------+       |
    |                       发车成功                       |
    +---------------------------------------------+-------+
                                                  v
                                              [任务投票]
                                             (missionVote)
                                                  |
          +---------------------------------------+----------------------+
          |                                       |                      |
          v                                       v                      v
    成功达 3 次                            失败达 3 次              未达 3 次
          |                                       |                      |
          v                                       v                      v
   [刺杀阶段] --刺杀-->                   [游戏结束] -----------> 下一轮(round+1)
          |                                 (坏人胜利)               |
          v                                                          |
     [游戏结束] <----------------------------------------------------+
     (好人胜/坏人胜)                  --> 回到轮次循环顶部 [预选]
```

> 图示说明：`[队伍投票]` 下方 `| 通过` 表示发车成功；`+--+` 为流车回环（下一位车主回到预选）。`[任务投票]` 三出口分别对应累计成功/失败/继续循环。

### 2.2 特殊环节（a-d）

| 环节 | 触发条件 | 插入位置 | 说明 |
|------|---------|---------|------|
| **a) 强制车** | 流车数达 `maxFailedNominations` | 替代预选/发言序 | 直接进入 discussion，按钮显示"强制发车"，发车后跳过 teamVote 直达 missionVote |
| **b) 刺客随时开刀** | 刺客（或莫甘娜）任意阶段点"开始刺杀" | 任意阶段 | 从"查看身份"弹窗进入刺杀阶段；刺杀阶段仅刺客可选目标 |
| **c) 湖仙验人** | 配置启用且完成轮次达 `ladyOfTheLakeRound` | missionVote 成功后、下一轮前 | 插入 lake 阶段（湖仙必验、令牌传递） |
| **d) 兰斯洛特转换** | 配置启用且存在兰斯洛特 | 轮次转换时 | 插入 lancelot 阶段（自动抽卡、全员确认） |

### 2.3 轮次循环说明

- 每轮内：`[预选] → [发言序] → [讨论] → [队伍投票]` 可能因流车重复多次（每次由下一位车主发起）。
- 发车成功 → `[任务投票]` → 按累计成功/失败数分支。
- 5 轮必出结果（每轮非成即败，累计 3 次即达标），不存在"5 轮后平局"情况。

### 3.3 AI 机器人命令速查

```bash
# 在 server 目录下运行
node scripts/ai-http.js <cmd> --key=value ...

# 房间与开局
create  --openId=bot_host --count=5          # 建房+4bot入座+全部准备
ready   --room=ROOM --openId=bot_x
start   --room=ROOM --openId=HOST_ID         # 房主开局
state   --game=GAME --openId=OPENID          # 查看状态

# 阶段推进（车主用）
confirm     --game=GAME --openId=bot_x       # 确认身份
prenominate --game=GAME --openId=bot_x --team=a,b,c   # 提交预选
order       --game=GAME --openId=bot_x --order=asc    # 选发言方向
nominate    --game=GAME --openId=bot_x --team=a,b --forced=0  # 确认发车
teamvote    --game=GAME --openId=bot_x --vote=approve  # 队伍投票
missionvote --game=GAME --openId=bot_x --vote=success --role=loyal  # 任务投票

# 刺杀
startAssassination（前端 role-modal 按钮）   # 进入刺杀阶段
assassinate  --game=GAME --openId=bot_x --target=bot_y  # 刺杀目标
```

> 说明：`startAssassination` 为前端按钮（刺客打开"查看身份"弹窗可见）；bot 侧可直接用 `assassinate`（需先进入刺杀阶段）。

## 4. 测试用例

> 每用例标注【前置 / 步骤 / 预期】。需 bot 配合的用例标注"bot 命令"。

### A. 开局与身份（roleReveal）

#### A1 开局身份页（全屏）展示视野列表
- **前置**：游戏开局（roleReveal）
- **步骤**：点"查看身份"进入全屏身份页
- **预期**：显示角色名 + 阵营 + 视野列表（头像/昵称/角色或阵营标签）+ 角色描述；梅林看2坏（莫甘娜+刺客）、派西维尔看梅林+莫甘娜（不区分身份）、忠臣无视野

#### A2 查看身份弹窗（去描述 + 视野）
- **前置**：已进入 preNominate 或后续阶段
- **步骤**：点"查看身份"打开弹窗
- **预期**：角色名 + 阵营 + 视野列表；**无角色描述**；点"隐藏身份"关闭且不自动消失

#### A3 全员确认进入 preNominate
- **前置**：roleReveal
- **步骤**：逐个确认（人类点"确认身份"，bot `confirm`）
- **预期**：未全确认停留 roleReveal 且计数递增；最后一人确认后自动进入 **preNominate**（不再卡"等待确认身份"页）

#### A4 5人局无湖仙标签
- **前置**：任意阶段
- **步骤**：观察玩家卡片标签
- **预期**：**无任何玩家**显示"湖仙"标签（5人局未启用湖仙，`lakeHolderOpenId=null`）

### B. 车主预选（preNominate）

#### B1 复选框选人/取消
- **前置**：车主进入 preNominate
- **步骤**：点玩家卡片或右侧复选框
- **预期**：选中=紫底白勾 ✓；再点=取消（空心灰圈）

#### B2 提交预选进入 speakingOrder
- **前置**：车主已勾选队员
- **步骤**：点底部"提交预选（N人）"
- **预期**：进入 **speakingOrder** 阶段

#### B3 轮询不覆盖本地选择
- **前置**：车主在 preNominate 已勾选若干人
- **步骤**：等待 >5 秒（轮询）
- **预期**：复选框选中**保持不变**

#### B4 新轮次本地选择清空
- **前置**：进入新一轮 preNominate
- **步骤**：观察复选框
- **预期**：**全部未选中**（不残留上一轮选择）

#### B5 非车主视角
- **前置**：非车主在 preNominate
- **步骤**：观察
- **预期**：底部显示"等待队长预选..."；**无复选框**（仅车主可见）

### C. 发言顺序（speakingOrder）

#### C1 车主选方向进入 discussion
- **前置**：车主在 speakingOrder
- **步骤**：点 ↑ 或 ↓
- **预期**：进入 **discussion**，底部显示所选方向

#### C2 预选车展示（无箭头）
- **前置**：speakingOrder
- **步骤**：观察底部框
- **预期**：显示"预选车：1 4"（座位号空格相连）；**无**紫色箭头（箭头仅 discussion 展示）；预选成员卡片有橙色"预选"标签

### D. 讨论（discussion）

#### D1 预选车 + 方向箭头
- **前置**：discussion
- **步骤**：观察底部框
- **预期**："预选车：1 4" + 紫色圆形箭头 ↑/↓（margin 与文字间距适度）

#### D2 车主可改选车
- **前置**：车主在 discussion
- **步骤**：点玩家复选框
- **预期**：可增删队员，`确认发车 N/需N人` 数字实时更新

#### D3 选车人数上限限制
- **前置**：车主在 discussion，需 N 人
- **步骤**：选中达到 N 人后，点剩余玩家复选框
- **预期**：剩余玩家复选框**变灰禁用**（不可选）；已选玩家可取消（降人数后可继续选）

#### D4 非车主无"等待队长发车"提示
- **前置**：非车主在 discussion
- **步骤**：观察底部框
- **预期**：仅显示预选车 + 方向，**无多余文字提示**

#### D5 计时器卡片隐藏
- **前置**：房间未设置 speechTimeout（或不限）
- **步骤**：进入 discussion
- **预期**：**无计时器卡片**；若设置了 speechTimeout，显示秒表卡片（仅房主可见启动/暂停/重置）

#### D6 确认发车人数初始正确
- **前置**：进入新轮次 discussion
- **步骤**：观察"确认发车 N/需N人"
- **预期**：**初始即正确**（如第2轮显示 0/3），不出现 0/2→1/3 的跳变

### E. 队伍投票（teamVote）

#### E1 投票按钮
- **前置**：teamVote
- **步骤**：点"同意"/"反对"
- **预期**：投票成功，无"已投 X/X"文字（已移除）

#### E2 车队成员金色渐变
- **前置**：teamVote
- **步骤**：观察发车队伍成员卡片
- **预期**：卡片右半**金色渐变**（#FEF3C7）→ 中间50%纯白

#### E3 已投票紫色渐变
- **前置**：teamVote
- **步骤**：投完后观察已投玩家卡片
- **预期**：已投票玩家左半**紫色渐变**（#DDD6FE）→ 50%纯白；车队+已投=左紫右金

#### E4 发车成功 / 流车
- **前置**：全员投票完成
- **步骤**：观察
- **预期**：多数同意→missionVote；多数反对→preNominate（下一位车主，round 不变，流车数+1）

### F. 任务投票（missionVote）

#### F1 任务按钮显示
- **前置**：missionVote
- **步骤**：观察
- **预期**：任务队成员见"成功/失败"按钮；非队员见"等待任务队执行"

#### F2 车队渐变保留
- **前置**：missionVote
- **步骤**：观察车队成员卡片
- **预期**：右半金色渐变保留

#### F3 票型绿/红渐变
- **前置**：missionVote（队伍投票结果已公开）
- **步骤**：观察所有玩家卡片
- **预期**：左半渐变按票型：赞成=绿（#D1FAE5）/ 反对=红（#FEE2E2）；车队成员右半金色保留

#### F4 底部赞成/反对座位号
- **前置**：missionVote
- **步骤**：观察底部框
- **预期**："赞成：1 2 3 4 5"（绿色）/ "反对：..."（红色），座位号**正序**排列，无票整行隐藏

### G. 刺杀（assassination）

#### G1 刺客任意阶段"开始刺杀"
- **前置**：任意阶段（刺客/莫甘娜）
- **步骤**：点"查看身份"→ 弹窗点红色"开始刺杀"
- **预期**：进入 **assassination** 阶段；非刺客玩家弹窗无此按钮

#### G2 刺杀阶段展示睁眼狼
- **前置**：assassination
- **步骤**：观察玩家卡片
- **预期**：睁眼狼（莫甘娜/刺客/爪牙/莫德雷德）卡片**淡红背景**（#FEE2E2）+ **红色角色名标签**（如"莫甘娜"）；奥伯伦/兰斯洛特不可见；所有玩家看到的睁眼狼信息一致

#### G3 刺客选目标刺杀
- **前置**：assassination，刺客视角
- **步骤**：点目标玩家
- **预期**：弹确认框 → 刺杀 → gameEnd（命中梅林→坏人胜/未命中→好人胜）

### H. 强制发车

#### H1 流车 3 轮进入强制车
- **前置**：房间 maxFailedNominations=3
- **步骤**：队伍投票连续流车 3 次
- **预期**：第 3 次流车后**直接进入 discussion**（跳过 preNominate/speakingOrder），`forcedSend=true`

#### H2 强制发车按钮文案
- **前置**：forcedSend=true 的 discussion
- **步骤**：观察车主底部按钮
- **预期**：按钮显示"**强制发车** N/需N人"（非"确认发车"）；点后直接 missionVote（跳过 teamVote）

### I. 历史记录

#### I1 车次记录完整展示
- **前置**：至少完成 1 车
- **步骤**：点"历史"打开弹窗
- **预期**：每轮显示 `第X车 · 车主 X号` / `发车：座位` / `同意：座位` / `反对：座位` / `结果：任务成功/失败`；流车车次结果"流车"

### J. 游戏结束与返回

#### J1 好人胜（3任务成功 + 刺杀未命中）
- **前置**：好人完成 3 任务 → assassination
- **步骤**：刺客刺杀非梅林
- **预期**：gameEnd 显示"好人胜利"🎉；揭示全部角色

#### J2 坏人胜（3任务失败 或 刺杀命中梅林）
- **前置**：坏人 3 任务失败，或刺杀命中
- **步骤**：触发条件
- **预期**：gameEnd 显示"坏人胜利"💀

#### J3 返回房间
- **前置**：gameEnd
- **步骤**：点"返回房间"
- **预期**：**能回到房间页**（不卡死）；房间 game_started 重置，玩家留在房间

## 5. 完整流程脚本

### 场景 1：三好车 → 刺杀成功 / 失败
```
开局 → 3 轮任务全部成功 → 自动进入刺杀阶段
→ 刺客点"查看身份"→"开始刺杀"（或已自动进入）
→ 刺杀阶段：所有玩家看到睁眼狼淡红卡片
→ 刺客选目标：命中梅林→坏人胜；未命中→好人胜
```

### 场景 2：三坏车 → 坏人直接获胜
```
开局 → 3 轮任务全部失败（坏人在任务队投 fail）→ 直接 gameEnd 坏人胜
（无需进入刺杀阶段）
```

### 场景 3：流车 3 轮 → 强制车
```
开局 → 每轮队伍投票投反对（流车）→ 连续 3 次
→ 第 3 次流车后直接进入 discussion（forcedSend=true）
→ 车主看到"强制发车"按钮 → 点后直接 missionVote
```

### 场景 4：刺客随时开始刺杀 + 睁眼狼展示
```
任意阶段 → 刺客打开"查看身份"弹窗 → 点"开始刺杀"
→ 进入刺杀阶段 → 所有玩家看到睁眼狼（淡红卡片+角色标签）
→ 刺客选目标刺杀 → gameEnd
```

## 6. 核心回归路径（优先测试）

A1→A3（开局确认）→ B1-B4（预选+轮询）→ C1-C2（方向）→ D1-D6（讨论+人数限制）→ E1-E4（队伍投票）→ F1-F4（任务投票）→ I1（历史记录）→ G1-G3（刺杀）→ J1-J3（结束返回）
